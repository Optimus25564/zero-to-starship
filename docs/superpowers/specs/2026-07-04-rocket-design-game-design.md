# 从零到星舰 · 火箭设计教学游戏 — 设计文档

> 工作名（暂定）：**Zero to Starship / 从零到星舰**
> 日期：2026-07-04
> 状态：设计已确认，待写实现计划

## 一、愿景

面向**完全零基础的小白**，做一款"边玩边学"的网页 3D 游戏，重走火箭工程的完整原理链条——从牛顿第三定律，一路到星舰完全复用、飞向火星。玩家在每一关**亲手动手**（调参数 / 拼装 / 排时序 / 实时操控）解决一个真实的工程难题，在动手与即时反馈中理解背后的物理原理。

**核心体验目标**：让一个从没学过物理的人，玩完之后能真正说清"火箭为什么能飞、为什么能回收、星舰凭什么革命"。

## 二、玩法定位（已确认的选择）

| 维度 | 选择 | 说明 |
|---|---|---|
| 玩法类型 | **关卡式解谜/教学**（轻量级） | 每关聚焦一个原理，门槛低、易迭代 |
| 主线组织 | **按工程原理由浅入深**（知识树） | 原理难度作骨架，历史事件作例子/彩蛋 |
| 交互模型 | **四种混合，内容决定玩法** | 调参 / 拼装 / 时序编排 / 实时操控，每关挑最贴切的一种 |
| 平台 | **网页**（发链接即玩） | Three.js，零安装，迭代快 |
| 渲染 | **写实 PBR + 示意图叠加层** | 平时写实火箭；学习环节叠加受力箭头/剖面/实时公式 |

## 三、内容骨架：完整原理知识树（愿景全集，约 30 小节 / 8 章）

原则：**面向小白、关键环节不漏、工具层层叠加**（后面的关卡复用前面学到的原理）。

**第一章 · 火箭凭什么飞（基础力学）**
- 1.1 作用力与反作用力、推力从哪来（质量流 × 排气速度）— 调参
- 1.2 推重比 TWR：离地的门槛 — 调参
- 1.3 齐奥尔科夫斯基火箭方程：Δv、比冲 Isp、为什么 90% 是燃料 — 调参

**第二章 · 发动机（能量之源）**
- 2.1 燃烧室 / 喷管 / 膨胀比 — 调参 + 剖面示意
- 2.2 推进剂之争：RP-1 vs 液氢 vs 液氧甲烷（星舰为何选甲烷）— 选择/对比
- 2.3 发动机循环：燃气发生器 → 分级燃烧 → 全流量分级燃烧（猛禽）— 拼装 + 示意
- 2.4 深度节流：着陆为何非它不可 — 调参

**第三章 · 结构与分级**
- 3.1 多级火箭：为什么要"扔掉一部分自己" — 拼装
- 3.2 级间分离：热分离 vs 冷分离、时序 — 时序编排
- 3.3 结构与材料：铝锂合金 vs 不锈钢（星舰的反直觉选择）— 选择/对比
- 3.4 贮箱增压：自生增压 autogenous — 调参

**第四章 · 上升与入轨**
- 4.1 重力转弯：不是往上飞，是往旁边飞得够快 — 实时操控
- 4.2 最大动压 Max-Q 与气动、整流罩 — 调参/时序
- 4.3 轨道力学：近地点/远地点、入轨速度 — 调参 + 轨道示意
- 4.4 二级燃烧与入轨精度 — 时序

**第五章 · 姿态与控制**
- 5.1 推力矢量 TVC — 实时操控
- 5.2 栅格舵 grid fins — 实时操控
- 5.3 反作用控制 RCS（真空里怎么转身）— 实时操控
- 5.4 GNC 闭环制导：机器怎么自己稳住 — 概念 + 可视化

**第六章 · 回收（核心难题）**
- 6.1 三次点火法：回推 → 再入 → 着陆点火 — 时序编排
- 6.2 再入热环境与减速 — 调参
- 6.3 软着陆：深度节流 / 悬停 / 着陆腿（《月球着陆器》式）— 实时操控
- 6.4 海上无人船 ASDS vs 陆地回收 — 决策

**第七章 · 星舰：完全复用**
- 7.1 隔热瓦与再入热防护 — 拼装/覆盖
- 7.2 腹部下坠 belly flop — 实时操控
- 7.3 翻转点火 flip maneuver（游戏高潮）— 实时操控
- 7.4 "筷子夹" Mechazilla 发射塔回收 — 实时操控

**第八章 · 深空与未来（系统级）**
- 8.1 轨道交会与对接 — 实时操控
- 8.2 轨道推进剂加注 orbital refueling — 时序/操控
- 8.3 快速周转经济学：成本/次，为什么复用是革命 — 经营模拟
- 8.4 通往火星：转移窗口 + EDL 火星进入下降着陆（综合关）— 综合

## 四、核心循环：单个关卡的 6 步结构

每一关都走同一套循环，这套循环本身就是"边玩边学"的引擎：

1. **钩子** — 一句真实 SpaceX 故事 / 抛出问题
2. **目标** — 一句话讲清本关要达成什么
3. **动手** — 写实 3D 火箭 + 本关交互（调参/拼装/时序/操控之一）
4. **模拟** — 点"发射"，3D 场景实时演出结果（升空 / 趴窝 / 爆炸）
5. **示意图学习层** — 结果出现的**同时**，火箭上叠加受力箭头、剖面、以及**随参数实时变化的公式**（学到东西的关键一步）
6. **通关与解锁** — 按表现打星 → 解锁下一关 → 弹出真实里程碑卡（照片 + 冷知识）

## 五、MVP 范围（第一版只做第一章）

**目标**：用第一章 3 关跑通并验证核心循环 —— "写实 3D + 示意图叠加 + 调参 + 实时公式"到底好不好玩、学不学得进去。同时把**关卡引擎 + 调参模块**打通，为后续 27 小节铺好底座。

**MVP 三关具体设计：**

- **1.1 推力从哪来**
  - 滑块：排气速度 vₑ、每秒喷出质量 ṁ
  - 表现：尾焰随参数实时变长/变粗
  - HUD 公式：`F = ṁ × vₑ`（实时变化）
  - 目标：把推力顶到目标值
  - 学到：推力 = 往后扔质量的反作用力

- **1.2 推重比 TWR**（在 1.1 基础上叠加）
  - 新增滑块：火箭总重
  - 表现：TWR < 1 火箭趴窝，> 1 升空；TWR 仪表盘
  - 目标：让火箭离开地面
  - 学到：光有推力没用，必须大于自重

- **1.3 火箭方程**（在前两关基础上叠加）
  - 新增滑块：燃料占比
  - 表现：Δv 随燃料比上升但边际递减（对数曲线可视化）
  - 目标：达到入轨速度 7.8 km/s
  - 学到：齐奥尔科夫斯基方程，"为什么火箭 90% 是燃料"

**工具叠加**：1.3 界面里 1.1/1.2 学到的推力与 TWR 依然在场。

**MVP 明确不包含**：真实物理引擎、第二章及以后内容、拼装/时序/操控三种交互模块、账号/存档云同步、音乐音效（可后加）。

## 六、技术架构

**技术栈**（为"轻量网页 3D + 单人快速迭代"而选）：
- **Three.js** — 3D 渲染，写实 PBR 火箭 + 示意图叠加层
- **Vite** — 开发服务器 / 打包
- **纯 JS + HTML/CSS** 做 UI 覆盖层（MVP 不引入 React 等重框架）
- **第一章无需物理引擎**：三条公式（F=ṁ·vₑ、TWR、火箭方程）直接确定性计算。真实物理引擎（如 Rapier）留到第六/七章实时着陆再引入。

**架构核心思想 —— 数据驱动的关卡引擎**（撑起 30 小节扩展性的关键）：

不给每关写死代码，而做一个**通用关卡引擎**读取每关的**配置数据**（滑块定义、目标、公式、示意图叠加、里程碑卡）。四种交互做成**可插拔模块**，每关按需选用。

```
关卡引擎（读配置 → 组装）
├─ 场景模块      Three.js 场景/相机/光照/火箭模型
├─ 交互模块      [MVP: 调参滑块] / 拼装 / 时序 / 操控
├─ 模拟核心      按本关公式算结果（确定性）
├─ 示意图层      受力箭头 + 实时公式 HUD + 剖面
├─ UI 层         目标/反馈/打星（HTML 覆盖）
└─ 进度与内容    解锁逻辑 + 里程碑卡数据
```

**各单元职责边界：**
- *关卡配置*（数据）：一份纯数据描述一关的全部内容；加新关卡 = 加一份配置。
- *场景模块*：负责 3D 呈现，输入是当前参数，输出是画面；不含游戏逻辑。
- *模拟核心*：输入参数 → 按公式输出结果（推力/TWR/Δv/是否达标）；纯函数，可独立测试。
- *示意图层*：订阅参数与模拟结果，渲染箭头/公式/剖面；只读，不改状态。
- *交互模块*：把玩家输入映射到参数；调参模块 = 一组滑块。
- *进度与内容*：管理解锁、打星、里程碑卡。

好处：MVP 做完第一章即打通引擎 + 调参模块；后续大量小节只是"写新配置 + 偶尔加新交互模块"，扩展成本大幅下降。

## 七、后续路线

1. 先实现 MVP（第一章 3 关），验证核心循环手感与教学效果。
2. 逐章扩展；每章新增所需的交互模块（拼装 → 时序 → 实时操控）。
3. 实时操控章节（第六/七章）引入物理引擎。
4. 视反响再考虑：音效、成就、把网页逻辑套壳成手机 App。
